# 前端重构规划：客户端化视觉重构（2026-07-29 拟）

> 背景：现前端按"编辑器"思路设计，作为客户端适配性弱，角色卡库体验最差（用户实测结论）。
> 本文是执行蓝图：基于两份交接材料规划重构路线，实施会话按此推进。
> 性质：只规划。实施时每阶段一个 commit + 满门禁。

## 0. 两份输入材料的关系与裁决

| 材料 | 定位 | 效力 |
|---|---|---|
| `_reference/前端设计交接/` | codex 辅助整理的**产品语义与设计边界**（信息架构、数据关系、红线清单、当前视觉基线样本） | 数据语义、故事工作区结构、"不要擅自改"红线**继续有效** |
| `_reference/新前端交接包/` | 用户与设计 agent 产出的**目标设计稿**（4 屏 demo：index.html 851 行 + layout.css 984 行 + themes.css 171 行，4 套主题） | **视觉与导航以此为准**，与旧交接冲突处按此执行 |

两者冲突处（均按新包执行，属用户后续迭代决策）：
1. 一级入口 3 个 → **4 个**（首页/角色库/编辑区/其他资产——"其他资产"升为顶级入口）
2. "处理区" → 改名"**编辑区**"（仅标签，路由 `/tools` 不动）
3. 单一暖纸张浅色 → **4 主题系统**（cocoa 深咖啡为默认，ink 墨黑、midnight 深夜蓝、cream 米色典雅承接旧视觉）
4. 设置图标齿轮 → **扳手**；侧栏底部 = 主题 + 设置两个入口
5. "接入 SillyTavern 目录"从侧栏 → **首页顶部显眼卡片**

## 1. 目标设计的可执行拆解（从 demo 提取）

**窗口级框架**（demo 全局结构）：
- 顶部标题栏（桌面应用感的品牌/搜索/导入/窗口区）
- Obsidian 式主侧栏：expanded 180px / collapsed 52px 双态；首页默认展开、其余页默认折叠；用户手动切换记 localStorage；文字随宽度 fade
- 底部状态栏（当前硬编码，需接真实数据）
- ⌘K 全局搜索框占位（逻辑未实现，本轮只放位置）

**主题系统**（themes.css，换肤唯一入口）：
- 全局层变量（跨主题不变）：`--brand` 品牌橙 `#E08A4A`（四主题缝合线）、`--status-*`、`--tag-*`、`--font-*`、`--radius-*`、`--sidenav-*`
- 主题层变量（每主题独立）：`--bg-canvas/chrome/elevated/elevated-strong`、`--border-*` 三档、`--text-*` 四档、`--hover-overlay`、`--input-*`
- 切换机制：`<html data-theme="cocoa">` + `localStorage['ste-theme']`；主题选择必须是弹层（不是 4 个小圆点）
- **禁止组件硬编码颜色**，一律 `var(--xxx)`

**二级导航（因页面而异）**：角色库 176px 筛选栏（数据集/标签色点/系统）｜编辑区 220px 列表（工作类型/处理队列/最近打开）｜其他资产 176px 筛选栏 + 主区分类 tabs｜首页无二级导航

**硬性红线**（新包"不要做的事" + 旧交接红线合并）：
<!-- 旧约束（已被真机反馈推翻）：角色卡 3:4 比例不可改；不加左上角编号 -->
- 角色卡采用 2:3 比例（ST 常见 400x600）；不加左上角编号
- 不把"接入 ST 目录"放回侧栏；不把"其他资产"做成顶栏 tabs 或藏进编辑区
- 数据语义红线照旧：分支属于故事、总结/日记/故事树不抽离故事上下文、独立资产+引用+写时复制、写回确认+备份
- 美学基调：**克制、暖、有仪式感，宁少勿多**；不明确处查 layout.css/themes.css，都没有 → 停下来问，不发明新颜色

现状摸底（利好）：
- 硬编码 Tailwind 色板类仅 **36 行 / 20 文件**，桥接清理量小
- `next-themes` 已在用（`attribute="class"`），支持改为 `attribute="data-theme"` + `themes: ['cocoa','ink','midnight','cream']`，Provider 不用换库
- shadcn 组件全走 CSS 变量（HSL token），把 `--background/--card/--border` 等映射到新主题层变量即可整体换肤

## 3. 技术方案要点

1. **主题基建（一切的前置）**：`themes.css` 原样引入 → `index.css` 里把 shadcn HSL token 桥接到新变量（每主题一组）→ `tailwind.config.ts` 扩展 `brand/canvas/chrome/elevated` 等语义色 → next-themes 切 data-theme 模式。cream 主题近似现状，可作过渡验证。
2. **侧栏状态管理**：`useSidenavState(pageDefault)` hook——页面默认值 + localStorage 用户覆盖，展开/折叠 transition 照 demo（width 0.2s + label opacity 0.15s）。
3. **标题栏两步走**：阶段一做**应用内标题栏**（保留系统窗口框），桌面感先到位；`decorations:false` 自绘窗口（拖拽/最大化需接 Tauri API）列为可选项，等阶段一稳定后再评估。
4. **深色主题专项风险**：`StoryMindmap`（内联亮色是导出刻意设计，需确认深色画布下的观感衔接）、`share-image.ts` canvas 长图配色、`GuidedTour` 遮罩、demo 立绘占位 `.art-placeholder-*` 换 `<img>`。
5. **路由零变更**：4 入口对应既有 `/`、`/library`、`/tools`、`/assets`，只动导航与标签，深链和引导教程选择器需同步检查。

## 5. 决策点（2026-07-29 已全部拍板）

1. **与 v1.0 发版的关系**：重构**并入发版前**。发布规划第二步复测改为重构完成后按新界面走。
2. **"快照"**：设计 agent 的误解，不设"快照"资产类别——资产页仍是世界书/预设/正则；后续会对接 ST 用户文件夹分析实际有哪些资源类型，届时再扩类别。
3. **首页内容**：demo 只参考**布局与主题**，具体内容按项目实际（沿用既定四块语义：角色库条/最近查看的故事/处理区/其他资产；无"继续游玩"）。
4. **标题栏**：授权执行方决定 → 阶段一做应用内标题栏保系统框；`decorations:false` 自绘窗口 P1 结束后视效果评估，不作承诺。

## 6. 本轮不做（防scope膨胀）

- ⌘K 搜索逻辑（只放占位）、自定义主题编辑器（弹层留入口）——demo 自己标注的未完成项
- 故事工作区/角色页的深度重设计（无设计稿，只换肤）
- WorldBook.tsx 1240 行等大文件拆分（仍属发版后重构项）
- 移动端适配（目标是 Windows 桌面 + 网页版，最小 1024×700）
