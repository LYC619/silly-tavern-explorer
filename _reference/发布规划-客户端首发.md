# 发布规划：带客户端的首次发版（2026-07-27 拟）

> 背景：2.0 改造与阶段 10 整改的代码面已完成，含 Tauri 客户端。2026-08-07 收尾仍按用户要求保留在本地，**不 push**；先完成三轮人工复测，再决定正式发布。
> 用户第一次发布带客户端的项目，本文档是执行蓝图，新会话按此推进。

## 核心认知（客户端项目和纯网页的区别）

1. **exe 不进 git**：`src-tauri/target/` 已在 .gitignore。客户端安装包通过 **GitHub Release 附件**分发，不是仓库文件。
2. **一次发版 = 三样东西**：git tag（代码快照）+ GitHub Release（发布说明）+ Release 附件（`STE_x.y.z_x64-setup.exe` 安装包，可再附免安装 `STE.exe`）。
3. **无签名警告**：exe 没有代码签名证书，用户下载后 Windows SmartScreen 会拦一次（更多信息→仍要运行）。README 里要写明这是预期行为；买证书或用 MS Store 是远期选项，个人项目一般不做。
4. **版本号四处同步**：package.json / `APP_VERSION`(GlobalSettings.tsx) / `public/sw.js` CACHE_VERSION / `src-tauri/tauri.conf.json`。前三处有 version-sync 测试守卫。

## 执行步骤（按序）

### 第一步：确认本地收尾提交后再 push
```
git push
```
- 当前阶段 10 任务明确要求不 push；只有用户检查本地提交并明确下令后才执行本步
- push 会触发 CI（.github/workflows/ci.yml：lint/真 tsc/vitest/build），届时确认首次远端执行结果
- push 只是备份与 CI 验证，不等于发版

### 第二步：真机复测通过（发版前置条件）
- 以 `三轮复测清单.md` 为唯一入口：已合并阶段 10 全部改动、二轮未测 5-9 节、统一测试遗留和真实 ST 写回链路
- 测出问题 → 修完再走第三步

### 第三步：收版 commit
- 版本号定为 **1.0.0**（用户已拍板：最终发布=1.0 正式；如想先放测试版就 1.0.0-beta，NSIS 支持预发布号）
- 四处版本号同步 + README 标题跟随 → `chore(release): v1.0.0`
- `npm run tauri build` 出正式安装包

### 第四步：打 tag + GitHub Release
```
git tag v1.0.0
git push origin v1.0.0
gh release create v1.0.0 --title "STE 1.0 —— ST 一站式归档库" --notes-file <发布说明>
gh release upload v1.0.0 "src-tauri/target/release/bundle/nsis/STE_1.0.0_x64-setup.exe"
```
- 发布说明：从 v0.17.1 以来的变化按用户视角写（2.0 改造九个阶段 + 客户端），不是 commit 列表
- 网页版部署照旧（Vercel/Docker 跟 main 走），客户端只认 Release 附件

### 第五步：README 更新
- 加「下载客户端」区：Release 链接、SmartScreen 说明、系统要求（Win10/11 x64，WebView2 Win11 内置）
- 网页版 vs 客户端差异一句话（客户端=文件库+ST 目录直连+写回；网页版=浏览器 IndexedDB）

## 远期可选（首发不做，记录备查）

- **CI 自动出包**：tauri-action 在打 tag 时自动构建并挂 Release（省去本机打包）；需要时再搭
- **自动更新**：Tauri updater 插件（应用内检查新版本），需要签名密钥对，等用户量再说
- **代码签名**：消除 SmartScreen 警告，需购证书（年费），个人项目通常跳过
