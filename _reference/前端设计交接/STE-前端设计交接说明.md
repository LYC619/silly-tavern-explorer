# STE 前端设计交接说明

> 这份文档给后续专门的设计 Agent 使用。它描述的是当前产品与当前前端基线，不是新的视觉方案。
> 配套样本：同目录下的 `STE-当前前端样本.html`，可直接双击打开，无需安装依赖。
> 视觉补充：用户反馈 `_reference/STE 概念设计/2.0草图存档/ste-home-structure-v4-preview.html` 的早期首页更舒服。该文件现在是优先视觉参考；本交接说明中的信息架构和数据语义仍以当前定稿为准。

## 1. 产品一句话

STE（SillyTavern Explorer）是给 SillyTavern 用户使用的个人故事归档与处理客户端：

- 在 SillyTavern 里游玩；
- 在 STE 里浏览角色卡、回看故事、整理总结和故事树；
- 也可以独立处理聊天、世界书、预设、正则和角色卡；
- 客户端模式可以读取本地资产，并在确认后写回 SillyTavern。

它不是聊天前端，也不是另一个 Tavern。主价值是“收藏、回味、整理、处理”。

## 2. 用户与使用场景

- 核心用户：已经在 SillyTavern 中游玩的个人用户。
- 首要动作：找一张角色卡、回看最近故事、打开故事工作区、整理历史内容。
- 次要动作：导入一个手头文件并处理，不要求先建立角色或故事档案。
- 使用设备：以 Windows 桌面客户端为主，也保留网页版。
- 目标窗口：1440×900；客户端最小约 1024×700；还要考虑半屏窗口和 125% 缩放。
- 用户习惯：角色卡是收藏入口；一个故事可以有多个分支；总结、日记、DIY 记录、故事树都是故事的下属资源。

## 3. 已确定的信息架构（不要在视觉重做时改掉）

### 一级入口

左侧主导航只有三个核心入口：

1. **首页**：角色卡图、最近查看的故事、处理区、其他资产。
2. **角色库**：角色卡列表与角色卡主页；故事工作区归在这里。
3. **处理区**：聊天、世界书、角色卡、预设、正则，以及客户端的 SillyTavern 接入。

设置在左侧导航底部，以齿轮入口进入独立设置页，不占主要导航位。

### 首页四块

当前首页的结构已经确定，优化重点是视觉层级而不是重新排列：

- **角色库**：顶部一行角色卡封面，作为收藏入口；显示角色卡数量。
- **最近查看的故事**：主体区域，最多显示最近看过的故事；包含角色缩略图、相对时间、楼数、最近模型、总结/日记/故事树/分支等资源标签。
- **处理区**：右侧较大的入口；突出“手上有文件，直接丢进来处理”。
- **其他资产**：右侧紧凑区域；世界书、预设、正则进入独立资产库。

首页不设置“继续游玩”主入口，因为用户在 ST 中继续游玩。

### 故事工作区

点击故事后进入 `/story/:id`，共享一个故事上下文（角色卡、故事、当前分支、阅读位置）。左侧二级栏当前包含：

- 阅读与编辑
- 整理与记录组：分卷总结、角色日记、自定义记录、故事树
- 导入与导出

阅读页还有分支、章节目录、书签和未绑定故事的绑定入口；正文工具栏有小说视图、沉浸阅读等入口。阶段 9 已退役旧的右侧资源栏，正文宽度回收。

### 角色卡主页

角色页包含：

- 角色封面（ST 卡片原图）
- 名称、简介、状态、评分、STE 标签
- 故事列表（楼数、时长、模型、最近查看、分支数）
- 关联资产（世界书、预设、正则）
- 客户端可选的立绘只读图墙

角色卡原文折叠区已按实测反馈移除；完整卡字段仍可从角色卡工具处理。

### 处理区与资产库

处理区支持拖入或选择：

- 聊天 JSONL / JSON / TXT
- 角色卡 PNG / JSON
- 世界书 JSON
- 预设 JSON
- 正则 JSON

程序先猜文件类型，用户确认后进入对应工具。聊天是最高频入口，视觉上应比其他工具更突出。

资产库是独立页面，分为世界书、预设、正则三个 tab。资产可以来自 ST、被角色引用、成为写时复制后的派生副本；点击资产条目才进入对应编辑工具。

## 4. 数据关系与产品语义

```text
角色卡
  └─ 故事（一个故事可有主线 + 多个分支）
       ├─ 阅读/编辑状态
       ├─ 分卷总结
       ├─ 角色日记
       ├─ 自定义记录
       ├─ 故事树
       └─ 导入/导出与写回记录

独立资产：世界书 / 预设 / 正则 / API 配置
  └─ 通过引用关联到角色或故事
```

关键语义：

- 分支是同一个故事的不同发展脉络，不是新的一级故事。
- 共享资产在角色上下文中修改时采用写时复制，派生文件名类似 `世界书_角色卡名`。
- API 配置是全局的、本机敏感的，不绑定角色；故事只记录使用过的模型信息。
- 删除 STE 角色档案不会删除 ST 原目录；名下故事转成未绑定。
- 写回 ST 必须经过差异确认，并自动备份；不能静默覆盖。

## 5. 当前技术边界

- React 18 + TypeScript + Vite。
- Tailwind CSS + Radix/shadcn 风格组件 + Lucide 图标。
- `BrowserRouter` 路由；页面按路由懒加载。
- 网页版使用 IndexedDB；Tauri 客户端使用明文 FileVault 文件库。
- 客户端：Tauri 2 + Rust；目标平台 Windows。
- 当前主要路由：

  `/`、`/library`、`/character/:id`、`/story/:id`、`/tools`、`/chat`、`/assets`、`/worldbook`、`/card-viewer`、`/preset`、`/regex`、`/settings`。

- `/ai-tools` 仅作为旧路径重定向到 `/settings`；`/bookshelf`、`/reader`、`/summary`、`/story-tree` 已退役或并入工作区。

## 6. 当前实现视觉基线（样本 HTML 应保持这些特征）

当前源码的视觉系统是“暖纸张 / 典藏工具”基线：

- 背景：暖米白、轻微纸张渐变。
- 主色：棕金/铜色；危险色为红色。
- 字体：正文 `Noto Serif SC`；标题偏 `ZCOOL XiaoWei`；代码和技术信息没有单独的强烈字体系统。
- 组件：圆角卡片、细边框、浅色表面、温和阴影、Lucide 线性图标。
- 交互：hover 边框变主色、按钮/卡片有轻微过渡、加载有淡入/骨架。
- 深色模式：已有 CSS 变量，但主要体验仍围绕浅色暖纸张设计。
- 布局：固定左侧主导航；内容区使用 flex/grid；避免依赖视口断点，尽量用可换行的 flex。

### 当前看起来“像网页工具”的原因

这些不是功能缺陷，而是后续设计 Agent 的主要改造对象：

1. 页面普遍使用相同的“标题 + 边框卡片 + 小按钮”语法，层级差异不够大。
2. 角色卡图与故事内容的视觉权重还不够突出，首页更像信息面板而不是个人收藏空间。
3. 工具入口、资产入口、状态标签都使用相近的卡片样式，主次不够明确。
4. 左侧导航、页面顶栏、二级导航、筛选条同时出现时，视觉节奏偏“管理后台”。
5. 文字字号和标题层级需要重新建立体系；尤其是列表文本不应与区域标题同等重量。
6. 细边框较多，阴影、表面层和留白还没有形成稳定的层级语言。
7. 空状态、加载状态、错误状态仍偏组件默认样式，缺少产品个性。
8. 当前有“客户端”的功能能力，但品牌、窗口级框架和桌面软件的完成感还不够。

### 6.1 早期概念设计：优先视觉参考

早期概念设计目录里有一套首页草图（`2.0草图存档/ste-home-structure-v4-preview.html`，同时有 PNG 预览）。它不是新的产品结构，而是更合适的视觉表达方向。后续设计 Agent 应优先研究这套首页的“舒服感”：

- 浅色、中性、接近纸张但不堆叠纹理的画布；
- 大面积留白和细水平分隔线，减少每个区域都套一张圆角卡片的感觉；
- 角色封面是首页最重要的视觉主体，名称和少量元信息贴近封面，不与区域标题争夺重量；
- 处理区作为右侧明确的第二主入口，聊天处理可以突出，但仍显示世界书、预设、角色卡、正则等工具；
- 最近故事与其他资产在下方并列，条目采用轻列表和小标签，不做待办面板；
- 顶部品牌、导航、搜索、导入和设置形成桌面应用的稳定框架；
- 首页以 1440×900 一屏可读为初始目标，超出内容进入“查看全部”，而不是把首页做成长滚动面板。

这套参考解决的是层级、留白和收藏感问题，不应被误读为要恢复旧的书架、继续游玩入口或独立故事资源导航。实现时仍必须保留本说明前面确定的语义：最近区域只列故事，分支属于故事，总结/日记/故事树属于故事，世界书/预设/正则是独立资产。

概念目录中的 `STE 2.0 界面草图 v2.html` 是另一套较完整的深色高保真卡片主页/阅读器参考，可按需吸收角色页和阅读器的排版细节；它不是首页视觉方向的强制替代品。

## 7. 后续设计 Agent 的任务边界

### 可以改

- 字体组合、字号比例、字重、行高。
- 色彩 token、表面层、边框、阴影、纹理和背景。
- 卡片、按钮、标签、筛选器、空状态、加载状态、弹窗的统一视觉语言。
- 首页四块的视觉权重与信息密度，但不改变四块的产品职责。
- 角色封面墙、故事卡、故事列表、工作区消息流的表现方式。
- 一级/二级导航的视觉层级、激活态、折叠态和桌面窗口感。
- 微动效、过渡、焦点态、键盘可见焦点和暗色模式对比度。

### 不要擅自改

- 不要把 STE 变成聊天前端或“继续游玩”入口。
- 不要把分支拆成独立一级故事。
- 不要把总结、日记、故事树等资源从故事上下文中抽离成新的主导航。
- 不要把世界书/预设/正则重新绑定为角色私有数据；它们是独立资产 + 引用关系。
- 不要在视觉重做中改变写时复制、ST 写回确认、备份恢复等数据安全语义。
- 不要为了视觉统一移除用户已有的模型、楼数、时长、分支、来源等元信息。

## 8. 建议的设计评审顺序

1. 先定整体视觉语言（质感、字体、表面层、颜色和图标规则）。
2. 再定首页四块的层级与卡片表达。
3. 再定角色页和故事卡的阅读/回味节奏。
4. 再定故事工作区的密度、消息流和二级导航。
5. 最后统一工具页、资产库、设置页，以及空/错/加载状态。

建议设计 Agent 先同时打开 `STE-当前前端样本.html` 和概念目录里的早期首页：前者用于核对真实页面、文案、数据和状态，后者用于提取更舒服的视觉语言。先做视觉替换和层级调整，不要一开始重构 React 信息架构。
