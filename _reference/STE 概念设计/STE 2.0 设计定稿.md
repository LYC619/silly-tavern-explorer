# STE 2.0 设计定稿

> 头脑风暴定稿文档。来源：2026-07-24 起的 codex 会话（`019f93d8-e3ab-7511-b6ee-a6898302de33`）+ 2026-07-26 Claude 会话续完。
> 本文档是后续规格、排期的唯一依据。只描述"做成什么样"，不涉及实现排期。

---

## 一、定位与原则

- **STE 是独立的一站式归档库，不是 ST 的同步伴侣。** 数据导入即在自己库里持有副本（Obsidian 式数据主权），ST 出错不丢档；不追求和 ST 的完全同步。
- **归档 = 玩后回味，不是数据处理流水线。** 不做"继续游玩"入口，不做强制流程、待办清单、自动串联。各功能独立可单用。
- **用户在 ST 里玩，在 STE 里收藏、回味、整理、分享。**
- 头脑风暴阶段只定信息结构和交互规则；像素级布局等做出真实网页后按实际体验调。

---

## 二、全局信息架构

```text
首页
├─ 角色库（主体）────────→ 角色卡主页 ──→ 故事工作区
├─ 处理区入口（第二主入口）→ 通用处理工具区
├─ 最近查看的故事 ────────→ 直达故事工作区
└─ 其他资产 ─────────────→ 世界书 / 预设 / 正则 / API 配置

数据关系：
角色卡
└─ 故事（= 一个 ST 聊天文件；分支是同一故事的不同发展脉络）
   ├─ 聊天正文
   ├─ 总结 / 日记 / 自定义记录 / 故事树
   ├─ 章节 / 书签
   └─ 归档元数据（模型、时长、所用资产版本）

世界书 / 预设 / 正则 = 独立资产，引用制 + 写时复制
API 配置 = 本机全局配置，不与角色绑定
```

## 三、首页

采用"私人收藏馆"方向（A2 为底 + A3 的最近整理）。

**四块内容：**

1. **角色库（主体）**：展示自己的角色卡收藏——封面、总数、标签、最近加入。ST 竖版封面统一 2:3 受控比例，原图尺寸不影响布局。
2. **处理区入口（第二主入口）**：明确展示可处理类型（聊天、世界书、预设、角色卡、正则），聊天入口视觉上可最突出，但不代表整个处理区。
3. **最近查看的故事**：只列故事；总结、故事树等以小标签显示为该故事已有的下属资源。轻量显示如"角色 A · 主线 · 436 楼 · Claude Sonnet"。不做待办清单。
4. **其他资产**：独立保存的世界书、预设、正则和 API 配置入口。

**硬约束：**

- 一屏无滚动，设计基准 **1440×900、100% 缩放**（可随实际体验调整，不是永久限制）；超出内容走"查看全部"进二级页。
- 标题层级：区域标题 ＞ 条目标题 ＞ 元数据 ＞ 资源标签。
- 不出现"继续游玩"。

## 四、角色卡主页

**定位**：角色卡的档案与回顾页。任务是看懂这张卡、回味故事、管理本地整理信息、进入处理工具。允许纵向滚动（一屏约束只针对首页）。

### 首屏身份区

- 左侧中等大小 2:3 封面，约占页面三分之一；右侧简介为主。
- 右侧：角色名、副标题、原始标签；STE 本地标签（首屏直接增删改）；统一状态；10 分制评分；简介；操作按钮。
- 操作：查看归档 / 处理此角色卡 / 重新生成简介。无"继续游玩"。

### 状态与标签

- 统一一组状态：**未开始 / 进行中 / 暂停 / 已完成 / 已弃置**。
- 状态由用户手动维护；系统可根据最近活动给建议，但不自动修改。
- 标签、评分、状态均为 STE 本地元数据，**不写回 ST 角色卡文件**。

### 简介

- 主体是整理后的可读简介；未生成时显示原始 Description 的整理版。
- **AI 简介**：用户手动触发；可读角色卡 + 关联世界书；新结果先作草稿与当前版比较，确认后替换并保留历史版本；源变化时只提示"可能已过期"，不自动覆盖。
- 原始角色卡字段（Description/Personality/Scenario/First Message）只保留一个入口，完整内容进角色卡处理工具（原文重要性偏低）。

### 评分

- 10 分制总分，点击打开侧边抽屉/弹层。
- 三种打分方式：直接手动；用模板（多维度+权重+理由，算参考总分）；AI 评分。
- 内置模板不可改，可复制后自定义维度、权重、提示词。
- AI 只给建议和理由，**用户确认后才保存为正式评分**；保存所用模板、提示词和生成时间。
- AI 读取范围每次由用户勾选：仅角色卡 / +世界书 / +指定故事，不默认读全部聊天。

### 故事历史

- 默认显示最近 5 个故事，"查看全部"进完整列表。
- 排序：无查看记录时按创建时间/编号；有记录后按最近查看。
- 故事行显示：标题、消息数、估算游玩时长、最近使用的模型、最近查看位置、阅读进度、分支数量（缺失字段不强行显示）。
- 点击故事直接进入故事工作区并定位上次查看位置；分支树由独立按钮展开。
- 分支不是独立故事条目，是同一故事的发展脉络；根条目默认折叠并标注"X 条分支"。

### 元数据读取规则（已核对 ST JSONL）

- 模型：读 `extra.model` / `extra.api`；重掷后的消息读当前 `swipe_info[swipe_id]`，不能只看顶层字段。
- 游玩时长：按消息时间戳把连续活动合并为时段，**间隔超过 15 分钟算新时段**；优先用 `gen_started/gen_finished`，缺失回退 `send_date`，不可靠时显示"未统计"。
- 故事另记录：使用过的模型列表、当时所用世界书/预设/正则的版本——只作归档元数据，不占主要界面。

### 关联资产区

- 简介旁的紧凑区域，每行：资产名、类型、共享/派生状态、最近修改时间。
- 点击先进只读概览，明确点"处理"才进工具区（角色上下文中修改触发写时复制）。
- API 配置不出现在此页。

## 五、故事工作区

点击故事进入。**共享同一个故事上下文**：所属角色卡、当前故事、当前分支、上次阅读位置、选中楼层范围、关联资产。左侧导航切换三个一级界面，上下文全程保留。临时导入的聊天可先在通用工具区处理，之后绑定已有故事或创建新故事进入这里。

> 本质：不是新功能，是把现有聊天处理、总结、故事树、导出能力放进同一个故事上下文。

### 5.1 界面一：阅读与编辑

- 默认连续滚动，保留沉浸式翻页模式。
- 左栏：分支树 + 章节目录 + 书签；右栏（可收起）：书签/总结/日记/故事树快速查看与草稿创建，完整编辑去界面二。
- 正文样式可切换，默认小说式。
- **每条消息直接点编辑（ST 用户习惯）**；保存先写入 STE 本地版本，原 ST 文件不动。编辑当前 swipe 时同步维护 `mes`、`swipes[swipe_id]`、`swipe_info`。
- Swipe：正文显示当前选中候选，提供切换控件查看/选择/编辑其他候选。
- 消息的模型、时间、token 信息默认收起，点信息按钮查看；时间戳可全局开启。
- 隐藏楼层、OOC、系统内容全部保留并标类型，显示开关控制。
- 正则只影响显示，可选是否应用于正文视图，原始文本永不改。
- 支持选中连续楼层 → 快捷生成总结/日记/故事树节点/书签/导出片段（沿用现有楼层选择+预设/世界书挂载逻辑）。
- 分支切换保留共同前文和各分支独立的阅读位置；章节可手动标记或主动调用 AI 生成（结果为可编辑草稿）。

#### 小说视图（阅读增强，非独立功能）

三层管道，导出 MD/分享图复用同一管道：

1. **纯文本层（免费、即时、主力）**：清洗（正则/HTML/状态栏/OOC）→ 楼内拆句重排（引号对白独立成段、星号旁白合并为叙述段、缩进标点规整）→ 用户楼层三档位（默认**弱化显示**，一键**隐藏**——AI 楼通常复述用户动作，隐藏几乎不丢信息——或保留为对白）→ 利用时间戳：楼间隔超长自动插场景分隔符"✦ ✦ ✦"。
2. **章节层**：沿用章节机制；AI 只看分卷总结/抽样定边界和标题，不读全文。
3. **AI 润色层（可选付费动作）**：按章走自定义记录的"小说化"模板重写，用户点了才花钱。

> 已实证的教训：纯连排/缩进/按楼数分章效果差。病根 = 用户楼层文风不搭、楼内结构没拆开、按楼数切章切不到场景边界。

### 5.2 界面二：整理与记录

三栏：**左资源索引 / 中预览编辑 / 右来源与操作**。

- 索引统一列出：分卷总结、角色日记、**自定义记录**（显示具体模板名，如散文型总结、史记型总结、人物分析）、故事树。支持按类型/模板/分支筛选、搜索、显示来源楼层和草稿状态。
- 日记按篇目/生成顺序/修改时间选择，**不按故事内日期全局排序**（不同故事日期互相冲突）；篇目内部保留原始日期，沿用现有日记本样式。
- 进入默认打开最近创建或修改的记录。
- 中间主区按资源切换：总结/自定义记录用 Markdown 读写；故事树切换为完整树编辑器（仍在工作区内）。编辑器复用现有功能，不重做。
- 右栏显示：所属角色卡/故事/分支、来源楼层范围、生成所用模型/预设/世界书条目/提示词模板、时间。操作：跳回聊天对应楼层（保留分支）、重新生成、复制为新记录、导出。
- 生成流程沿用现状：选分支和楼层范围 → 选是否挂预设/世界书及条目 → 选模板 → 生成草稿 → 编辑确认保存。每条记录存**生成参数快照**，可复现。原文不被修改。

### 5.3 界面三：导入与导出

只管当前故事的聊天文件进出（独立资产不在这里）。进入页面不自动扫描，只显示来源路径、绑定状态、上次导入/导出时间。

**① 检查 ST 更新（仅客户端）**

- 打开故事时轻量比对原 jsonl 楼层数，有新楼在角落提示"ST 里多了 20 楼"，点击才导入。
- 导入规则：新楼直接追加；同一楼两边不同时**不做逐条 diff 界面**——ST 新版当正文，STE 编辑版转成该楼 swipe 并标"STE 编辑版"。完成后一句摘要："新增 20 楼，2 楼有改动已存为 swipe"。
- 网页版等价操作 = 手动重新导入文件，合并规则相同。

**② 导出副本**

- 聊天：ST 兼容 JSONL / TXT / Markdown（沿用现有楼层范围、正则、清理选项）。
- 总结、日记：Markdown；故事树：JSON / Markdown。
- **美化分享图**（附加项，不占主流程）：一期先做总结长图（故事名+角色封面+总结正文），日记/故事树/聊天名场面后续跟上。分享图也是传播渠道。

**③ 写回 ST（仅客户端，仅已绑定原路径的故事）**

- 手动导入的故事标"未绑定"，此区域不出现，只能导出。
- 写回前自动备份原文件，保留最近若干版，可一键恢复；只显示简单摘要（改了几楼/删了几楼），确认后执行，记录写回历史。

## 六、通用处理工具区

**定位**：首页第二主入口，解决"我手上有个文件要处理"，不要求先建档。

- **入口主页**：大拖放区 + 工具列表。丢文件后弹**类型选择**（程序给默认猜测，用户确认）——选择器即适配层，未来接其他角色扮演工具 = 加类型选项 + 导入适配器，工具本身不动。
- **聊天工具**：与"阅读与编辑"同一套界面。临时文件顶部标"未绑定"，随时绑定角色卡/创建故事，绑完原地升级为故事工作区。未绑定状态下总结、故事树照常可用，绑定时成果带走。
- **世界书 / 预设 / 角色卡**：沿用现有编辑器。三个打开路径：资产库打开；临时导入（处理完可"存入资产库"或直接导出，不强迫入库）；角色卡关联资产区点"处理"（带角色上下文 → 写时复制）。
- **正则**：独立工具——规则管理、批量导入、**可视化生效预览**（选文本或某楼，直观看到每条规则改了哪里、哪条没命中）。聊天工具里保留"应用正则"选项。规则入资产库。远期可能与脚本、框架合并为"扩展"分类（先记下不展开）。
- **书架退役**：收藏/进度/状态职责由"角色库 + 故事"承接，不再有独立书架页。

## 七、独立资产与写时复制

- 世界书、预设、正则独立存在，类似 Obsidian 引用，可同时关联多个角色/故事；角色和故事只记引用关系，不各自复制。
- **写时复制**：在某角色上下文中修改引用资产时——原资产不变；生成派生副本，命名 **`原资产名_角色卡名`**（如"霍格沃茨通用设定_赫敏"）；记录 `derivedFrom`、关联角色 ID、创建/更新时间、是否仍与原版有差异、写回目标；该角色的引用切到副本；后续修改更新同一副本，不重复新建。其他引用者不受影响。
- 后续可做"查看与原版差异""恢复引用原版"，暂不做自动合并。
- **API 配置**：客户端全局配置，与角色/故事无引用关系。Key、Base URL 等敏感信息只存本机；故事只记录非敏感使用信息（模型 ID、显示名、时间）。

## 八、客户端整体流程

### 存储

**纯明文文件库**：一个文件夹 = 整个库，全部是人能直接打开的文件；用户可网盘同步、手动备份。索引缓存不是架构承诺，性能不够时再加，加了也可随时删除重建。

### 库目录

```text
我的STE库/
├─ 角色/
│  └─ 赫敏/
│     ├─ 卡片.png              ← 角色卡原件
│     ├─ 档案.json             ← 简介、评分、标签、状态 + 自定义字段
│     ├─ 立绘/                 ← 图片直接丢进去就算数
│     └─ 故事/
│        └─ 主线/
│           ├─ 聊天.jsonl      ← STE 工作版
│           ├─ 总结·卷一.md
│           ├─ 日记·第3篇.md
│           └─ 故事树.json
├─ 临时/                       ← 未绑定的导入聊天；绑定后移入对应角色
├─ 资产/
│  ├─ 世界书/（含派生副本）
│  ├─ 预设/
│  └─ 正则/
└─ .ste/                       ← 写回备份等内部数据，可删可重建
```

**自定义原则**：STE 只管自己认识的文件，**不认识的文件原样保留、永不删改**（Obsidian 同款规则）。用户可自由塞立绘、语音、参考图，或在档案.json 加自定义字段；能展示的展示，不能展示的列出来。

### 首次接入 ST

指定 ST 目录 → 扫描列出角色卡/聊天/世界书清单（带数量体积）→ 用户勾选 → 复制进库并记住来源路径。不全量强导。

> 技术前提已确认：ST 的聊天/世界书/角色卡全是本地纯文本/PNG 文件（`data/default-user/` 下），客户端只需文件读取权限，不需要 ST 运行、不需要插件或 API。

### 版本关系与其他

- 同一套代码：**客户端 = 网页版 + 目录读取/检查更新/写回/文件库这层壳**；网页版继续 IndexedDB，仅少这几项能力。客户端壳以 Tauri 为候选，选型留到规格阶段验证。
- 旧数据（现有书架/IndexedDB）**不迁移**，2.0 干净起步（未发布，无真实用户数据）。
- API Key 等敏感配置存系统配置目录，**不进库文件夹**（防止随库同步/分享泄漏）。
- 两条数据路径通用规则：任何写回都不静默覆盖；手动导入的内容随时可导出。
