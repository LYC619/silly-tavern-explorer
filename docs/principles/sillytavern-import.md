# SillyTavern 导入与资产关系

## 安全边界

STE 把所选 SillyTavern 目录当作只读来源。扫描和导入不会移动、删除或改写来源文件。导入的第三方扩展只作为文件副本归档，STE 不加载或执行其中代码。

## 当前扫描与去向

| SillyTavern 来源 | STE 去向 | 行为 |
| --- | --- | --- |
| `characters/*.png` | `角色/<角色名>/` | 解析角色档案并保留 PNG 原件 |
| `chats/<角色>/*.jsonl` | 对应角色的 `故事/` | 解析为故事；无对应角色或坏卡的聊天进入 `临时/` |
| `worlds/*.json` | `资产/世界书/` | 解析为可编辑世界书 |
| `OpenAI Settings/*.json` | `资产/预设/` | 解析为聊天补全预设 |
| `settings.json -> extensions.regex` | `资产/正则/` | 整组导入为一套全局正则 |
| `extensions/` | `资产/其他/SillyTavern/extensions/` | 递归原样复制，保持相对路径，不执行 |
| `assets/` | `资产/其他/SillyTavern/assets/` | 递归原样复制，保持相对路径 |

选择角色卡时，会同时选择 `chats/<角色>/` 下的全部聊天。散聊天、世界书和预设可逐项选择；`extensions/` 与 `assets/` 以目录组选择。

## 世界书关系

导入器先建立世界书名称到库内 ID 的索引，再导入角色和聊天，恢复以下关系：

| 关系 | SillyTavern 来源 | STE 记录 |
| --- | --- | --- |
| 卡内嵌世界书 | `data.character_book` | 提取为独立世界书并在角色上标记“卡内嵌” |
| 主绑定 | `data.extensions.world` | 角色引用已导入的同名世界书，标记“主绑定” |
| 额外链接 | `settings.json -> world_info_settings.world_info.charLore[].extraBooks` | 按角色卡文件名匹配，标记“额外链接” |
| 全局世界书 | `settings.json -> world_info_settings.world_info.globalSelect` | 在对应世界书上保存全局启用标记 |
| 对话级世界书 | JSONL 首行 `chat_metadata.world_info` | 在故事上保存“对话级”引用 |

名称匹配忽略 `.json` 后缀和大小写，并优先使用当前 ST 根下 `worlds/` 的精确来源文件。没有当前来源文件时，只接受唯一的手动同名资产；存在多个同名候选或只有其他 ST 根的同名文件时不自动猜测。目标缺失或名称有歧义时，STE 会在角色档案和本次导入结果中保留“未解析关联”的原名称及原因。

重新扫描时，主绑定、额外链接、全局启用和对话级关系按当前 SillyTavern 状态重建；已经取消的关系不会继续残留。全局关系记录 `settings.json` 的来源，不同 ST 根互不清理。`settings.json`、已有聊天或已有角色卡损坏时，本次不会把空结果当成有效状态，也不会清除或回滚对应的已有关系。手动添加且没有 ST 关系标签的引用不受影响。

如果角色已通过写时复制把某个 ST 世界书变成角色专属派生副本，来源关系没有改绑时，重新扫描继续保留派生副本；只有 ST 明确改绑到另一份来源世界书时才切换目标。

## ZIP 备份导入

STE 也接受由独立 ST 扩展导出的 ZIP。ZIP 只作为一次性的只读输入源：客户端解压到受限临时目录，仍复用本页的扫描、选择和入库流程，目标数据始终写入用户当前选择的 STE 库；临时目录在取消、失败或完成后清理，不写入 `stRoot` 配置。每个 ZIP 都视为一次新的导入，不承诺跨 ZIP 去重或增量同步。

当前扩展导出范围是角色卡、角色聊天、世界书、OpenAI Settings 预设和全局正则。群组/群聊、Persona、附件和其他模型后端预设等内容不在该 v1 导出范围内；这不改变本地 ST 目录导入对已支持目录的处理规则。

## 导入结果与重复项

完成后界面显示新增、其他资产、恢复关联、未解析、已跳过和失败的逐项结果。其他资产可以在“附属库 → 其他”中只读查看；完整结果保存在 STE 库：

- `说明/SillyTavern 导入说明.md`
- `说明/SillyTavern 最近一次导入.json`

角色、聊天、世界书、预设和正则以绝对来源路径判断是否已导入。同一路径再次选择时不会创建副本；已导入角色目录中新出现的聊天仍会绑定到原角色，已有聊天只刷新对话级世界书关系，不覆盖库内消息。`extensions/` 与 `assets/` 重新选择时更新 STE 内同路径的归档副本，SillyTavern 来源保持不变。

扫描不会跟随符号链接，也拒绝包含路径分隔符、`.` 或 `..` 的异常目录项名称。客户端在每次实际读写前还会基于所选根目录重新检查路径，防止扫描后文件被替换成链接。被跳过的链接、异常名称或超过遍历深度的目录会出现在扫描警告和最近一次导入清单中。

## 当前没有结构化导入的内容

群组、群聊、Persona、其他模型后端预设、主题、背景、快捷回复和向量索引尚未转换为 STE 业务对象。角色卡和聊天中的未知字段仍随原始数据保留；密钥文件不进入导入范围。
