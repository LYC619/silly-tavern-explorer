# 前端审查问题分批修复设计

日期：2026-07-31

## 目标

按第 0 至第 3 批依次修复已确认的前端问题。每批保持单一职责、独立测试、独立提交；不改变已确认的 2:3 角色卡比例，不在本轮调整版本号，也不进行无关重构。

## 非目标

- 不把开发版本 `0.18.0` 提前升级为 `1.0.0`。
- 不处理 Google Fonts 本地化、发布包版本同步和发布环境验收。
- 不重新设计页面布局、导航结构、字号层级或视觉风格。
- 不引入 Redux、全局事件总线或新的状态管理框架。

## 第 0 批：统一文档基线

### 现存问题

权威文档仍将角色卡比例写为 3:4，而最新真机反馈和当前实现已经确定为 ST 常见的 2:3。

### 不修复的影响

后续开发者或 Agent 可能依据旧文档把正确实现改回 3:4，造成重复返工。

### 设计

在两份权威文档中将有效规则改为 `2:3（ST 常见 400x600）`，原 3:4 规则保留为 Markdown HTML 注释，说明其已被真机反馈推翻。该批只修改文档。

### 验收

- 有效正文中不再存在 3:4 约束。
- 旧规则只存在于隐藏注释。
- Markdown 表格结构不被注释打断。

## 第 1 批：保证状态和阅读位置正确

### 现存问题

1. `STImportCard` 导入成功后只关闭弹窗，首页和编辑区仍显示导入前的数据。
2. `AppLayout` 使用模块级缓存保存 ST 接入状态，首次选择目录后不会立即更新。
3. Tauri 客户端使用 `navigator.storage.estimate()` 展示 WebView 存储量，与 FileVault 实际体积无关。
4. 首页使用故事总消息数冒充上次离开楼层，且未记录最近查看的故事分支。

### 不修复的影响

用户无法从界面确认导入是否真正生效；状态栏可能同时显示错误的接入状态和数据体积；首页会提供错误的阅读恢复信息，分支故事还可能回到错误脉络。

### 组件和数据流

- `STImportCard` 增加可选的 `onChanged` 回调。在成功保存 ST 根目录以及成功完成导入后通知父页面。
- 回调只负责通知。父页面刷新失败不得让已完成的导入被误报为“导入失败”。
- `Home` 和 `Tools` 将现有首屏查询整理为各自的 `useCallback` 刷新函数，初次挂载和 `onChanged` 共用同一函数。
- `AppLayout` 接收显式的状态刷新标识。首页或编辑区收到 `onChanged` 后递增标识，使状态栏重新读取配置。
- 删除模块级永久状态缓存。Web 端仍可显示 `navigator.storage.estimate()`；Tauri 端本轮不显示体积，避免展示错误数据。
- `ArchiveStory` 增加可选的最近查看分支标识。缺省值代表主线，保持旧归档兼容。
- 故事工作区切换分支时记录该标识；首页通过该标识和 `getBranchLine` 读取对应脉络的 `lastFloor`。没有阅读位置时不使用总楼数伪造进度。

### 错误处理

- 数据刷新失败沿用页面当前的静默空态，不回滚已成功导入的数据。
- ST 配置读取失败时状态栏显示未接入或不显示扩展信息，不阻塞应用。
- 最近分支不存在时安全回退到主线。

### 验收

- 首页导入后角色、故事、世界书、预设和正则数量立即更新。
- 选择有效 ST 目录后，状态栏无需重载即可更新。
- Tauri 不再显示 WebView 存储量为“本地数据”体积。
- 主线和分支均显示真实离开位置，旧归档无需迁移即可使用。
- 新增针对回调、刷新触发和分支阅读位置的测试。

## 第 2 批：让四主题覆盖阅读器和辅助文字

### 现存问题

`ReaderView` 与 `NovelView` 使用固定浅色和固定黑色背景，三套深色主题进入全屏阅读后退化为同一个界面。状态栏整体应用透明度，部分 9 至 11px 辅助文字对比度不足。

### 不修复的影响

主题切换只在应用外壳有效，进入核心阅读流程后失去差异；小字号状态信息在 Cream 和深色主题下均较难辨认。

### 设计

- 全屏阅读容器改用已有的 `--bg-canvas`、`--bg-elevated`、`--text-*` 和边框变量。
- 不修改阅读器结构、分页逻辑、工具栏尺寸或排版设置。
- 移除状态栏容器整体透明度，直接选择合适的文字 token。
- 仅将承担实际信息传达的低对比度小字从 `--text-faint` 提升到 `--text-muted`；装饰性内容保持原层级。

### 验收

- Cocoa、Ink、Midnight 和 Cream 的全屏阅读背景与当前主题一致。
- 四主题仍具有可辨认的色彩差异。
- 状态栏和关键辅助标签达到普通小字可读水平。
- 不产生布局位移或组件尺寸变化。

## 第 3 批：修正交互语义和资产分类

### 现存问题

1. 角色卡、角色列表行和资产卡的主要操作由不可聚焦的 `div onClick` 承担。
2. 首页入口使用上传图标和“丢进来”文案，但实际只跳转到编辑区。
3. 完整 ST 接入卡同时出现在首页和编辑区。
4. “工具入库”未排除 `autoSaved`，资产来源计数发生重叠。

### 不修复的影响

键盘用户无法可靠打开卡片；首页给出错误的拖放暗示；重复接入入口挤占编辑区；来源筛选数量不能代表互斥资产类别。

### 设计

- 卡片主要内容改为可聚焦的语义化主操作，Enter 和 Space 可触发；下拉菜单保持独立的兄弟操作，避免交互元素嵌套。
- 补充 `focus-visible` 样式，鼠标视觉和现有卡片布局保持不变。
- 首页入口改为明确的“进入编辑区”语义，不复制编辑区的文件识别和类型确认逻辑。
- `STImportCard` 支持完整和紧凑两种既有内容密度：首页保留完整接入说明，编辑区仅保留轻量重新扫描命令。
- 资产来源统一使用单一分类函数，优先级为：派生副本、自动保留、来自 ST、工具入库。每项资产只计入一个来源。

### 验收

- 鼠标行为不变，键盘可以看到焦点并打开卡片。
- 首页不再暗示可以直接接收文件。
- 编辑区不再重复展示完整接入卡，但仍能发起重新扫描。
- 来源分类数量互斥，所有分类之和等于当前资产总数。

## 分批验证与提交规则

每批按以下顺序执行：

1. 先补充能够复现目标问题的测试。
2. 只修改该批列出的模块，不做顺手重构。
3. 检查完整 diff 和 `git diff --check`。
4. 运行 TypeScript、ESLint、Vitest 和生产构建。
5. 涉及归档数据结构时额外运行 Rust 测试。
6. 该批验证通过后形成独立提交，再开始下一批。

若某批需要改变本设计中的数据字段、交互语义或视觉层级，应暂停并重新确认，不自行扩大范围。
