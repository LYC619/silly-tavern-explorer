# 界面约定

> 这些是 STE 内部的界面一致性约定，不是使用说明。定它们的原因：项目主力是 AI 辅助开发，
> 「同一件事上一次是怎么写的」如果只存在于某个文件里，下一次就会长出第二种写法。
> 每条约定后面都写了理由——理由不成立时可以改，但要连着理由一起改。

## 一、图标方向：导入向下，导出向上

**箭头朝下 = 文件落进 STE；箭头朝上 = 内容从 STE 送出去。**

| 语义 | 图标 | 例子 |
|---|---|---|
| 导入、拖入、从备份恢复、重新导入 | `Download` / `DownloadCloud` / `FileDown` | 导入世界书、拖入角色卡、选择文件重新导入 |
| 导出、另存 | `Upload` / `FileUp` | 导出角色卡、导出 .md、导出完整备份 |
| 写回 SillyTavern | `FileUp` | 数据离开 STE 去 ST 那一侧，和导出同向 |

`Cloud` / `File` 变体按场景自由选（整页拖入落点用 `DownloadCloud`，文件相关的小按钮用
`FileDown`/`FileUp`），**只有箭头方向是硬约定**。

**别用「下载」当按钮文案。** 应用给你一个文件一律叫「导出」，配向上箭头。
（浏览器状态类的提示可以说下载，如「已请求下载 N 张角色卡」——那说的是浏览器在做什么，
不是按钮在做什么。）

### 为什么是这个方向

2026-08 扫描时仓库里两套约定各占一半（21 : 17），按主流惯例定这一条：箭头描述的是
**文件相对应用的运动**——外面的东西落进来是向下，里面的东西送出去是向上，
这是 import / export 托盘图标的经典语义。

两个附带好处：

1. **写回 ST 不用再找补。** 数据离开 STE 去 ST 那边，和导出同向，`FileUp` 直接对上。
   反过来的规则要么给它开例外，要么解释成「写回也是一种进」。
2. **拖入落点是向下箭头**，和「文件掉进这个框里」的动作一致。

唯一要盯住的坑：这条规则下「导出」是向上箭头，所以**文案里不能再出现「下载」**，
否则就会有「下载」配向上箭头。E1 顺手把仅有的两处（`下载 PNG`、`下载 .md`）
统一成了「导出」——同一个动作别处本来就一律叫导出，那两处是异类。

## 二、术语

### 计数单位：楼

一条故事有多少条消息，**一律说「N 楼」**，不说「N 条消息」。

- 「楼」是量词：`共 120 楼`、`新增 20 楼`
- 「楼层」是名词：`楼层号`、`楼层范围`、`跳转到楼层`
- 楼层号 0-based，对齐 SillyTavern

例外：在讲解析规则、逐条处理逻辑时说「消息」是对的（「每段作为一条消息」「按每条消息
处理」）——那里说的是数据结构，不是在数这条故事有多少楼。

### 一条故事的四个名字

同一个 `ArchiveStory`，在不同语境下是不同的词，**不要互换**：

| 词 | 指什么 | 用在哪 |
|---|---|---|
| 故事 | `ArchiveStory` 本身 | 用户可见文案的默认词 |
| 聊天 | 故事里的正文/消息，或聊天处理页 | 「聊天记录」「聊天处理」 |
| 会话 | `story.session`，代码层概念 | 只在注释和标识符里用，不进 UI |
| 暂存故事 | 未绑定角色的故事 | 聊天处理页空态 |

「暂存」这个词在仓库里还盖着另外两件事（自动暂存的记录草稿、世界书跨页暂存）。
三者语义确实不同，重命名牵扯用户已有数据的心智模型，**留给整体重构处理，别顺手改**。

### 附属库的两级

- 一级区域叫 **附属库**（`navigation-model.ts` 的 `assets`）
- 二级是 **世界书 / 预设 / 正则 / 其他资产**
- 「其他资产」特指从 SillyTavern 归档过来的扩展等只读文件，不是「附属库」的同义词

## 三、入口落点

**世界书和预设的入口一律进选择页**（`/tools?focus=worldbook`、`/tools?focus=preset`），
不直接进空编辑器。`/worldbook`、`/preset` 是选完之后的编辑器路由，不作为入口。

理由见 `RegexTool.tsx` 里那条注释：用户从入口点进来看到一个空编辑器，会以为自己点错了。

## 四、加载与空态

加载文案统一用 `lib/ui-copy.ts` 的 `LOADING_LABEL`，约定写在那个文件的注释里。

**空态是一句结论，读完之前不能下这个结论。** 任何「还没有 X」的空态都必须有 loading 分支，
读失败要显式报错并说明数据仍在库里，不能静默显示空态。

## 五、两个 Toaster 是故意的，别删

`App.tsx` 同时挂了 shadcn `<Toaster />` 和 `<Sonner />`：

- 业务提示全部走 `@/hooks/use-toast` → 渲染在 `<Toaster />`
- **Service Worker 的「新版本可用」提示走 sonner**（`lib/register-sw.ts`），
  需要 `duration: Infinity` 和 action 按钮，渲染在 `<Sonner />`

`<Sonner />` 看起来零调用是因为它的唯一调用方在 `register-sw.ts` 里直接 `import { toast }
from 'sonner'`，不经过 hook。删掉它，网页版的更新提示会静默消失，而且不报错。
